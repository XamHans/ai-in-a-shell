# One canvas, grounded sections

For one connected working question, continue in the existing canvas and keep its ID, current
content, and source references. State the problem in a prominent heading and short explanation;
show the evidenced current state separately from clearly labeled proposals and alternatives.
Use existing nodes, groups, text, and supported fields. Do not create a tab for topology, sequence,
or solution by default; add a detail tab only for a separate question or at the user's request.
Preserve the user's organization; explanatory labels do not require fixed groups or folders.

The canvas is optional. Use it only when available and useful; never claim an action, capability,
or visibility change that the host does not provide. Respect requests for text, direct help, or
separate tabs. Preserve existing content and distinguish code-derived facts, observed runs,
inferences, and proposals. A proposal is not a completed or observed run. Do not save private
learning evidence automatically; use its explicit consent flow.

This is a presentation default, not a new canvas schema. See the [canvas components reference](canvas-components.md)
for supported structures and limits.
